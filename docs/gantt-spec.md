# ガントチャート仕様 v0.1

## 1. 目的

PMがプロジェクトの計画・実績・進捗・遅延を一画面で把握し、進捗会議や日常管理で利用できるガントチャートを提供する。

本仕様では、一般的なガントチャートの考え方を基準としつつ、初期段階では機能を絞り、GAS + Googleスプレッドシートで実用可能な構成を優先する。

## 2. 基本構造

ガントチャートは以下の3層を基本とする。

1. プロジェクト
2. 工程・フェーズ
3. タスク

表示上は、1行を1タスクとする。

工程・フェーズは複数タスクをまとめる親行として扱い、必要に応じて折りたたみ・展開できる構成を想定する。

例：

- 要件定義
  - 業務ヒアリング
  - 要件整理
  - 要件レビュー
- 設計
  - 基本設計
  - 詳細設計
- 開発
  - API実装
  - 画面実装

## 3. タスク項目

v0.1では各タスクに以下を保持する。

| 項目 | 内容 |
|---|---|
| task_id | 一意なタスクID |
| project_id | 所属プロジェクトID |
| parent_task_id | 親工程・親タスクID。最上位はNULL |
| task_name | タスク名 |
| assignee | 主担当 |
| planned_start_date | 計画開始日 |
| planned_end_date | 計画終了日 |
| actual_start_date | 実績開始日 |
| actual_end_date | 実績終了日 |
| progress_percent | 進捗率 0〜100 |
| status | 未着手 / 進行中 / 完了 / 保留 |
| priority | 高 / 中 / 低 |
| predecessor_task_id | 先行タスクID。初期は任意 |
| note | 備考・PMコメント |
| updated_at | 最終更新日時 |

## 4. 進捗率

v0.1では進捗率は手入力とする。

初期実装では、工数消化率や子タスクからの自動算出は行わない。

理由は、実務上の進捗率は単純な工数比率と一致しないことが多く、初期段階ではPMまたは担当者の判断を優先するためである。

入力範囲は0〜100とし、100の場合は原則として完了状態と整合していることを求める。

## 5. ステータス

入力値として以下を持つ。

- 未着手
- 進行中
- 完了
- 保留

「遅延」は入力ステータスではなく、日付と進捗から自動判定する。

## 6. 遅延判定

v0.1では以下のルールで判定する。

### 6.1 開始遅延

以下を満たす場合、開始遅延とする。

- 今日 > 計画開始日
- actual_start_date が未設定
- status が未着手
- status が保留ではない

### 6.2 終了遅延

以下を満たす場合、終了遅延とする。

- 今日 > 計画終了日
- status が完了ではない
- status が保留ではない

### 6.3 完了

status が完了、または progress_percent = 100 の場合は完了として表示する。

ただしデータ保存時には status と progress_percent の整合性を検証する。

### 6.4 保留

status が保留の場合は、v0.1では遅延判定対象外とする。

将来的に保留理由や再開予定日を持たせる可能性がある。

## 7. ガント表示

画面は左右2領域で構成する。

### 7.1 左側：タスク情報

最低限、以下を表示する。

- 階層表示
- タスク名
- 担当者
- 進捗率
- ステータス

必要に応じて計画終了日も表示する。

### 7.2 右側：日付軸

日付軸上にタスクの期間を表示する。

初期表示は日単位とし、週単位への切り替えを可能とする。

### 7.3 計画と実績

計画期間と実績・進捗は識別可能にする。

推奨表現：

- 背景側のバー：計画期間
- 前景側のバー：実績期間または進捗状況

これにより、開始遅延・終了遅延・進捗不足を視覚的に把握できるようにする。

### 7.4 今日表示

現在日を縦線または背景強調で表示する。

## 8. 階層表示

親工程・親タスクは展開・折りたたみ可能な表示を想定する。

v0.1では階層の深さは固定しないが、実運用上は3階層程度を推奨する。

例：

- プロジェクト
  - 工程
    - タスク

必要以上に深い階層は操作性を損なうため推奨しない。

## 9. 親タスクの期間

v0.1では親タスクの計画期間は以下のいずれかとする。

- 手入力
- 子タスクの最小開始日〜最大終了日から表示上算出

初期実装では、子タスクから表示上算出する方式を優先候補とする。

ただし保存データとして親タスクの日付を持つかは、実装設計時に確定する。

## 10. 依存関係

v0.1では先行タスクを1件まで保持できる構造を用意する。

ただし、以下は初期対象外とする。

- 自動日程調整
- 依存関係変更による後続タスクの自動移動
- クリティカルパス計算

将来的には、先行タスク未完了の状態で後続タスクが開始されている場合などに警告できるようにする。

## 11. 編集操作

ガント画面から以下を行えることを想定する。

- タスク追加
- タスク編集
- タスク削除
- 進捗率変更
- ステータス変更
- 計画日変更
- 実績日変更
- 担当者変更
- 備考・コメント変更

初期UIでは、一覧から別ページへ遷移するよりも、行選択時に右側または下部へ編集パネルを表示する方式を優先する。

## 12. 表示切替

v0.1では以下を想定する。

- 日表示
- 週表示

月表示は将来候補とする。

## 13. フィルタ・絞り込み

最低限以下を想定する。

- プロジェクト
- 担当者
- ステータス
- 遅延のみ

## 14. 画面上の注意表示

以下を視覚的に識別可能とする。

- 正常
- 注意
- 遅延
- 完了
- 保留

色や具体的なUI表現は画面設計で定義する。

## 15. v0.1対象機能

以下をv0.1の対象とする。

- プロジェクト単位のガント表示
- 階層タスク
- 計画開始・終了
- 実績開始・終了
- 担当者
- 進捗率
- ステータス
- 遅延自動判定
- コメント
- 日 / 週表示切替
- タスク追加・編集・削除
- 基本的な絞り込み

## 16. v0.1対象外

以下は初期対象外とする。

- 工数管理
- 原価管理
- 予算管理
- 複数担当者
- リソース山積み
- クリティカルパス
- 自動スケジュール調整
- Jira / GitHub等との同期
- AIによる遅延予測
- 高度なベースライン比較

## 17. 未確定事項

実装前に以下を確定する。

1. 親タスクの日付を保存するか表示上算出するか
2. 実績バーを実績日ベースで表示するか進捗率ベースで表示するか
3. 進捗率とステータス不整合時の補正ルール
4. 先行タスクを1件に限定するか複数許可するか
5. 日表示・週表示の初期表示範囲
6. タスク行の固定列構成
7. スマートフォン対応範囲
8. 大量タスク時の表示上限・ページング方式
