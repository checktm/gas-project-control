# 問い合わせ概要・詳細仕様

## 1. 目的

メール件名と業務上の問い合わせ内容を分離して管理する。

同一メールまたは同一Gmailスレッドから複数の問い合わせが発生する場合、メール件名だけでは問い合わせを識別できないため、Inquiryに業務上の「概要」と「詳細」を持たせる。

この文書は `docs/inquiry-management.md` の `Inquiries.summary` の扱いを補足・更新する。

## 2. 項目の役割

- `subject`: メール由来の件名。受信情報として保持し、業務上の問い合わせ名としては使用しない。
- `summary`: 問い合わせを一覧や見出しで識別する短い概要。
- `detail`: 問い合わせの経緯、要点、確認事項などを記載する詳細。
- `next_action`: 次に行う対応。

## 3. 初期値

新しいInquiryを作成した時点では、`summary` の初期値にメール件名 `subject` を設定する。

これは初期表示の便宜のためであり、利用者は問い合わせ内容に合わせて `summary` を編集できる。

同一メールから別問い合わせへ分離した場合も、新しいInquiryの `summary` 初期値は分離開始メールの件名とする。

## 4. 既存データ移行

旧仕様では `summary` が詳細説明として利用されていたため、`detail` 列が存在しない既存環境では次の一回限りの移行を行う。

1. `Inquiries` に `detail` 列を追加する。
2. 旧 `summary` の値を `detail` へ移す。
3. `summary` は各Inquiryの `subject` で初期化する。

移行後は `summary` が空の新規データだけ、`subject` で補完する。

## 5. UI

問い合わせ一覧では `summary` を主表示し、メール件名 `subject` は補助情報として表示する。

管理情報では次の順に表示する。

1. 概要
2. 詳細
3. 次回対応

詳細画面上部の見出しも `summary` を使用し、メール件名は補助情報として表示する。

検索対象には、概要、詳細、メール件名を含める。

## 6. AI支援

メール履歴のAI要約は、短い問い合わせ名である `summary` を置き換えるのではなく、`detail` の候補生成として扱う。

AI返信案では、`summary`、`detail`、`next_action`、対応期限、メール履歴を参考情報として利用する。AI生成結果は自動保存・自動送信しない。
