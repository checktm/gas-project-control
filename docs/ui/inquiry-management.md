# 問い合わせ管理 UI仕様 v0.1

## 1. 目的

受信メールから自動登録された問い合わせを、PM・管理者が一覧で把握し、顧客特定、担当割当、状態更新、次回対応管理まで一画面で行えることを目的とする。

## 2. 画面構成

アプリ上部の主要機能切替に以下を持つ。

- ダッシュボード
- 問い合わせ
- マスタ管理

問い合わせ画面は、左側の一覧と右側の詳細・編集領域の2ペイン構成とする。

PCでは右側詳細を「管理情報」と「メール対応」に分ける。管理情報は保存ボタンまでを一画面内で確認・操作できる密度を優先し、メール対応はメール履歴の確認を優先する。

## 3. 問い合わせ一覧

表示項目:

- 最終受信日時
- 顧客名
- 顧客担当者または送信元
- 問い合わせ概要
- 自社担当者
- 状態
- 対応期限
- 優先度

顧客未特定の場合は「未特定」と明示する。

問い合わせ一覧では `Inquiries.summary` を問い合わせ概要として主表示する。メール件名は受信元情報として補助表示する。

問い合わせ概要の初期値はメール件名とし、その後利用者が業務上分かりやすい短い内容へ変更できる。

一覧は画面内で独立して縦スクロールできる。受信日時と問い合わせ概要の一覧性を優先し、問い合わせ概要は可能な範囲で2行まで表示する。

### 3.1 絞り込み

- フリーワード検索
  - 顧客名
  - 顧客担当者
  - メールアドレス
  - 問い合わせ概要
  - 問い合わせ詳細
  - メール件名
  - 分類
- 状態
- 優先度
- 顧客未特定のみ

### 3.2 対象外ドメイン

マスタ管理の「システム設定」に `問い合わせ対象外ドメイン` を表示する。

- 複数ドメインをカンマ、改行、セミコロン区切りで入力できる
- `example.com` を設定すると、そのサブドメインも対象外とする
- 設定後は、そのドメインから開始した問い合わせを問い合わせ一覧に表示しない
- ダッシュボードの件数・最近の問い合わせからも除外する
- データは削除しないため、設定からドメインを外せば再表示される

対象外判定はInquiryを開始した最初の受信メールの送信元ドメインで固定し、後続メールによって表示可否が変わらないようにする。

## 4. 詳細・編集

一覧行を選択すると、右ペインに問い合わせ詳細を表示する。

編集可能項目:

- 顧客
- 顧客担当者
- 状態
- 優先度
- 自社担当者
- 分類
- 対応期限
- 概要
- 詳細
- 次回対応

### 4.1 概要

問い合わせを一覧で識別するための短い内容。新規問い合わせではメール件名を初期値にする。

### 4.2 詳細

問い合わせ内容、経緯、条件などを整理する記述欄。旧仕様の「概要」に保持していた詳しい内容はこちらへ移行する。

問い合わせ詳細ヘッダーでは概要を主表示し、メール件名は補助情報として表示する。

受信情報として保持する以下は画面から編集しない。

- Gmail message ID
- Gmail thread ID
- メール本文
- メール件名
- 送信元
- 受信日時

## 5. 顧客・担当者

顧客を変更した場合、顧客担当者候補は選択した顧客に属する担当者へ絞り込む。

自動判定結果は以下を表示する。

- 担当者一致
- ドメイン一致
- 候補複数
- 顧客未特定
- 手動設定

利用者が顧客を変更した場合は `MANUAL` として保存する。

顧客未特定・候補複数の問い合わせは、現在の顧客・顧客担当者マスタを使って再判定できる。

## 6. メール対応

詳細上部の切替はPCでは以下の2つとする。

- 管理情報
- メール対応

### 6.1 メール対応画面

メール対応画面はメール履歴の確認を中心とする。

- メール履歴をできるだけ広い領域で表示する
- 履歴は新しい日時順で表示する
- 画面上部に `返信` ボタンを表示する
- 返信本文入力欄は常時表示しない

### 6.2 返信ダイアログ

`返信` ボタンを押すと大きな返信ダイアログを表示する。

PCでは以下の2カラムとする。

- 左: メール履歴
- 右: 返信編集

返信編集には以下を表示する。

- To
- CC
- 返信対象メールの日時・件名
- 返信本文
- AI返信案
- 送信状態
- 返信送信ボタン

CCは最新受信メールのCCを初期値とする。ただし主宛先との重複、自社メールドメイン、社内メンバー、問い合わせ受付アドレスは除外する。利用者はCCを追加・削除できる。

### 6.3 メール履歴

同一Inquiryへ紐づくInquiryMessageを新しい日時順で表示する。

表示内容:

- 受信 / 送信のバッジ
- 件名
- メール日時
- プレーンテキスト本文
- 受信メールの `別問い合わせ` 操作

`別問い合わせ` を押した場合、対象受信メールから後のメールを新しいInquiryへ分離する。

問い合わせ状態が解決済みかどうかでは分離を自動判定しない。

### 6.4 AI返信案

管理情報画面と返信ダイアログの双方に `AI返信案` を表示できる。

Geminiは管理情報とメール履歴を参照して返信本文候補を生成する。概要・詳細・次回対応など、生成時点の画面入力値を利用する。

生成結果は自動保存・自動送信しない。

## 7. AI詳細生成

詳細欄の近くにAI生成操作を表示できる。

メール履歴をもとに担当者が状況把握できる詳細候補を生成し、利用者が確認・修正して保存する。短い問い合わせ概要はAI生成によって自動上書きしない。

## 8. 保存

保存時はスプレッドシート `Inquiries` の管理項目のみ更新する。

参照整合性として以下を検証する。

- customer_id が Customers に存在すること
- contact_id が CustomerContacts に存在すること
- contact_id が選択customer_idに属すること
- assigned_member_id が Members に存在すること
- status / priority が定義済みコード値であること

## 9. マスタ管理 / システム設定

画面から以下を管理可能とする。

- 問い合わせ受付アドレス
- メール検索条件
- 1回の最大スレッド数
- メール自動取込
- 自社メールドメイン
- 問い合わせ対象外ドメイン

問い合わせ対象外ドメインを保存した場合、問い合わせ画面とダッシュボードは次回読み込みから新しい設定を利用する。

## 10. モバイル

スマートフォンでは一覧から問い合わせを選択すると詳細を全画面表示し、「問い合わせ一覧へ戻る」で一覧へ戻れる。

管理情報とメール対応の切替概念を維持する。返信ダイアログはスマートフォンでは全画面表示し、履歴と返信編集を縦方向に配置する。

## 11. 空状態

問い合わせが0件の場合は、メール取込設定後に自動登録される旨を表示する。

一覧未選択時は、右ペインに問い合わせ選択を促す表示を出す。

## 12. v0.1対象外

- 添付ファイル表示
- 問い合わせの手動新規作成
- 問い合わせ削除
- AIによる自動分類・自動優先度確定
- AIによる継続/別件の自動確定
- SLA自動計算
- Project / Taskへの直接変換UI
