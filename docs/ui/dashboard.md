# ダッシュボード UI仕様 v0.1

## 目的

日常業務の開始時に、問い合わせ対応の状況と主要マスタの登録状態を一画面で把握できるようにする。

また、開発中にWebアプリへ最新デプロイが反映されているか確認できるよう、現在表示中のビルド情報を画面に表示する。

## 初期表示

アプリ起動時はダッシュボードを初期表示とする。

ヘッダーの主要機能は以下の3つとする。

- ダッシュボード
- 問い合わせ
- マスタ管理

ガントチャートは引き続き非表示とする。

## KPI

以下を表示する。

- 未完了問い合わせ数
  - NEW / IN_PROGRESS / WAITING_CUSTOMER
- 新規問い合わせ数
- 顧客未特定件数
  - UNMATCHED / AMBIGUOUS
- 期限超過件数
  - 未完了かつ due_date が当日より前

## 最近の問い合わせ

last_message_at、未設定時は received_at の降順で最大6件を表示する。

表示項目は以下。

- 件名
- 顧客名
- 自社担当者
- 最終受信日時
- 状態

行を選択すると問い合わせ管理画面へ移動し、対象問い合わせを選択する。

## マスタ登録状況

有効な以下の件数を表示する。

- 顧客
- 顧客担当者
- 社内メンバー
- 問い合わせ分類

## メール取込状態

Settings の `MAIL_IMPORT_ENABLED` を参照し、有効 / 無効を表示する。

## デプロイ反映確認

GitHub Actionsによる開発デプロイ時に、以下を `APP_CONFIG` へ埋め込む。

- Git commit の短縮SHA
- ビルド日時

画面右側の「デプロイ反映確認」に表示する。

これにより、ブラウザで表示しているWebアプリがどのGitHub更新を反映しているか確認できる。

## データ更新

ダッシュボードの「更新」ボタンで集計を再取得する。

ダッシュボード集計は表示用の派生値とし、新しい集計シートは作成しない。
