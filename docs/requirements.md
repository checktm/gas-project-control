# gas-project-control 要件定義

## 1. 目的

PMが使用している進捗管理資料を、Google Apps Script（GAS）を利用したWebアプリとして再構築する。

単なる資料のWeb化ではなく、PMが以下を素早く把握・更新できることを目的とする。

- プロジェクト全体の進捗
- 遅延している工程・タスク
- 期限が近い工程・タスク
- 課題・リスク
- 次回アクション
- 担当者ごとの状況
- 進捗会議で確認すべき事項

## 2. 利用者

初期想定はPMを主利用者とする。

将来的には以下の利用者も想定する可能性がある。

- プロジェクトメンバー
- 管理者
- 経営層・マネージャー

権限管理の詳細は、実際の利用形態を確認したうえで別途定義する。

## 3. 初期機能要件

### 3.1 プロジェクト管理

プロジェクト単位で以下を管理できること。

- プロジェクトID
- プロジェクト名
- 顧客名または案件名
- PM
- 開始日
- 終了予定日
- ステータス
- 全体進捗率
- プロジェクト概要・コメント

### 3.2 工程・タスク管理

プロジェクト配下に工程・タスクを登録できること。

初期候補項目は以下とする。

- タスクID
- 親工程または親タスク
- タスク名
- 担当者
- 計画開始日
- 計画終了日
- 実績開始日
- 実績終了日
- 進捗率
- ステータス
- 優先度
- 備考

実際に使用する項目は既存のPM進捗管理資料を確認して確定する。

### 3.3 ステータス管理

少なくとも以下の状態を表現できることを想定する。

- 未着手
- 進行中
- 完了
- 保留
- 遅延

「遅延」を入力値として持つか、日付と進捗から自動判定するかは既存運用確認後に決定する。

### 3.4 課題・リスク管理

プロジェクトまたはタスクに対して課題・リスクを管理できること。

初期候補項目は以下。

- 種別（課題 / リスク）
- 内容
- 重要度
- 担当者
- 対応期限
- 対応状況
- 次回アクション
- コメント

### 3.5 PMコメント・次回アクション

進捗会議や日常管理で使用するため、PMが自由記述できるコメントおよび次回アクションを保持できること。

### 3.6 ガントチャート

工程・タスクを期間軸で表示できること。

初期要件は以下。

- 計画期間を表示
- 実績または進捗状況を識別可能
- 今日の位置を把握可能
- 遅延タスクを識別可能
- プロジェクトまたは一定範囲に絞り込み可能

詳細なUIは画面設計段階で定義する。

### 3.7 ダッシュボード

プロジェクト全体の状況を一画面で把握できること。

初期表示候補は以下。

- 全体進捗率
- 未完了タスク数
- 遅延タスク数
- 期限間近タスク数
- 未解決課題数
- 重要リスク数
- 今週の主要予定
- PMが確認すべき項目

既存進捗管理資料の内容を確認し、実務上必要なものに絞り込む。

## 4. 非機能要件

### 4.1 操作性

- ノートPCで主要な管理操作が行えること。
- 進捗会議中でも操作しやすいこと。
- 主要情報の確認に過度な画面遷移を要求しないこと。
- 一覧と編集の往復を少なくすること。

### 4.2 性能

初期段階では、小〜中規模のプロジェクト管理を想定する。

GASおよびGoogleスプレッドシートの制約を考慮し、一行ずつの頻繁なサーバー通信を避け、可能な範囲でまとめて読み書きする。

### 4.3 保守性

- UI処理、業務ロジック、スプレッドシートアクセスを可能な範囲で分離する。
- シート名・列番号などを画面処理へ直接散在させない。
- 項目変更時の影響範囲が分かりやすい構成とする。

### 4.4 データ整合性

- データ間の参照には安定したIDを利用する。
- 必須項目や日付の前後関係など、最低限の入力検証を行う。
- 更新失敗時に利用者が気付けること。

## 5. 想定データ保存先

Googleスプレッドシートを主なデータ保存先とする。

現時点で想定するシートは以下だが、既存資料の分析後に確定する。

- Projects
- Tasks
- Members
- IssuesRisks
- Settings

必要以上にシートを細分化しない。

## 6. 初期対象外

現時点では以下を必須機能としない。

- 高度な工数原価管理
- 請求管理
- 契約管理
- 複雑なワークフロー承認
- 外部顧客向けポータル
- 高度な権限制御
- Jira等との双方向同期

必要性が確認された場合に追加検討する。

## 7. 未確定事項

以下は現在使用しているPM進捗管理資料および実際の運用を確認してから確定する。

1. 現在の管理項目と必須項目
2. プロジェクト・工程・タスクの階層
3. 進捗率の入力方法・算出方法
4. 遅延判定ロジック
5. 課題とリスクの管理方法
6. 進捗会議で必要な集計値
7. 担当者・組織の持ち方
8. 複数プロジェクトを横断した表示の必要性
9. 更新履歴の必要性
10. 権限管理の必要範囲
11. スマートフォンで必要な操作範囲

## 8. 次の作業

現在使用中のPM進捗管理資料を確認し、以下を実施する。

1. 現行項目の棚卸し
2. 不要項目・重複項目の整理
3. GASアプリで追加すべき情報の検討
4. データモデル案作成
5. 主要画面構成案作成
6. 初期実装範囲の確定
